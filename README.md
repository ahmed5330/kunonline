# كن أونلاين — نظام إدارة متاجر العملاء

داشبورد لكل عميل بأرقام متجره، ولوحة إدارة تتحكم في كل حاجة، وربط تلقائي بإيزي أوردرز وتتبع شحنات J&T مصر.

يشتغل على Cloudflare Workers + D1. مفيش سيرفر تديره ولا تكلفة شهرية في البداية.

---

## المحتويات

| الملف | إيه ده |
|---|---|
| `public/index.html` | الداشبورد كله — لوحة العميل ولوحة الإدارة |
| `src/index.js` | السيرفر: تسجيل الدخول، الـ API، الويبهوك، تتبع الشحنات |
| `tests.mjs` | ٥٧ اختبار للدخول وعزل البيانات والويبهوك والتكاملات والواتساب والحسابات — `node tests.mjs` |
| `schema.sql` | جداول قاعدة البيانات |
| `wrangler.toml` | إعدادات النشر |
| `.dev.vars.example` | نموذج المتغيرات — **ما ترفعش النسخة الحقيقية** |

---

## التشغيل — ٧ خطوات

### ١. ارفع الملفات على GitHub
اعمل ريبو **Private** وارفع كل الملفات فيه. تقدر ترفعهم بالسحب والإفلات من موقع GitHub.

### ٢. اعمل قاعدة البيانات

```bash
npx wrangler d1 create konline
```

هيطلعلك `database_id` — انسخه وحطه في `wrangler.toml` مكان `ضع-الـ-database_id-هنا`.

### ٣. جهّز الجداول

```bash
npx wrangler d1 execute konline --remote --file=./schema.sql
```

### ٤. حط الأسرار

كل واحد فيهم بأمر منفصل، وهيسألك على القيمة:

```bash
npx wrangler secret put SESSION_SECRET              # نص عشوائي طويل، غيّره ما تستخدمش مثال
npx wrangler secret put EASYORDERS_WEBHOOK_SECRET   # من لوحة إيزي أوردرز (خطوة ٧)
npx wrangler secret put TRACKING_API_KEY            # من مزوّد تتبع الشحنات
npx wrangler secret put INGEST_TOKEN                # نفس التوكن اللي في .env بتاع OpenClaw (ad-spend-sync.py / konline-orders)
npx wrangler secret put TOKEN_ENC_KEY               # ٣٢ حرف عشوائي على الأقل — بيشفّر توكنز Meta/EasyOrders وكلمة سر الإيميل
```

> حساب الإدارة مش بيتحط هنا. أول ما تفتح الموقع بعد النشر هيطلب منك تعمله بإيميل وكلمة مرور،
> وبيتخزّن في قاعدة البيانات. الشاشة دي بتشتغل مرة واحدة بس وبعدها بتتقفل تلقائياً.

**الأسرار دي عمرها ما تتكتب في أي ملف داخل الريبو.** مكانها Cloudflare بس.

### ٥. انشر

```bash
npx wrangler deploy
```

أو — الأفضل — من لوحة Cloudflare: **Workers & Pages ← Create ← Connect to Git** واختار الريبو. بعدها كل تعديل تحفظه على GitHub بينشر لوحده.

### ٦. اربط الدومين

من إعدادات الـ Worker ← **Custom Domains** ← ضيف `app.kun-online.com`.
Cloudflare هيعمل سجل الـ DNS لوحده — ما تكتبوش بإيدك.

> سجل `www` بتاع جوجل سايت سيبه زي ما هو، وخلّيه **DNS only** (سحابة رمادية) مش Proxied.

### ٧. وصّل إيزي أوردرز

من لوحة التاجر: **Public API ← Webhooks ← Create Webhook**، وحط الرابط:

```
https://app.kun-online.com/webhooks/easyorders
```

هيولّدلك secret — حطه في `EASYORDERS_WEBHOOK_SECRET` (خطوة ٤).

بعدها من لوحة الإدارة ← تبويب **العملاء**، حط **معرّف المتجر في إيزي أوردرز** (`store_id`) لكل عميل. من غيره الأوردرات الجاية هتتجاهل لأن السيستم مش هيعرف هي بتاعة مين.

## إضافة عميل جديد

من **العملاء** في لوحة الإدارة:

1. اكتب بياناته و**كلمة مرور** له
2. حط **اقتصاديات الأوردر** (سعر الأوردر ومصاريفه) — منها بيتحسب الربح والهامش
3. حط `store_id` لو عنده متجر على إيزي أوردرز
4. ابعتله الإيميل وكلمة المرور على واتساب — وقوله يغيّرها من "الأمان" في آخر داشبورده

كل الحسابات بتتدار من تبويب **الحسابات**: إنشاء، تصفير كلمة المرور، إيقاف، حذف.

---

## الحسابات — الربح والخسارة لكل عميل

كل عميل عنده تبويب **"الحسابات"** في لوحته، والإدارة عندها نفس البيانات لأي عميل من تبويب **"التكاملات"**:

- **نسبة التسليم**: تلقائية (محسوبة من سجل حالات الأوردرات الفعلي: مُسلَّم ÷ (مُسلَّم + مرتجع))، أو يدوية يحطها العميل بنفسه
- **مبلغ الإدارة الثابت**: تحدده الإدارة لكل متجر على حدة، بيتخصم من ربح كل أوردر
- **ثلاث أرباح**: منتظرة (وصلت ولسه ما اتحصّلتش من شركة الشحن) · محصّلة فعلاً · متوقعة (كل الأوردرات المرفوعة × نسبة التسليم)
- **تكلفة الأوردر من فيسبوك**: قبل وبعد مراعاة نسبة التسليم
- **إيداعات فيسبوك**: يضيفها العميل يدويًا. (بحث: فيه طريقة لسحبها تلقائي عبر `GET /act_{id}/activities?fields=...` بفلترة `event_type=ad_account_billing_charge` — تحتاج اختبار عملي بتوكن حقيقي لتفعيلها لاحقًا)
- عدّاد الأوردرات اليومي بيتحدّث لوحده كل ٣٠ ثانية على داشبورد العميل

## الأوضاع — مضيء / مظلم / رمادي

زرار تبديل في أعلى الشاشة، والاختيار بيتحفظ في المتصفح (`localStorage`) فيفضل زي ما هو في الزيارة الجاية.

## التوكن والـ API + الضريبة + ربط الإيميل + الواتساب

كل عميل عنده تبويب **"التكاملات"** في لوحته، والإدارة عندها نفس الأقسام لأي عميل من تبويب **"التكاملات"**:

- **ميتا**: معرّف حساب الإعلانات + توكن اختياري خاص بالعميل (لو مش موجود، الأجنت بيستخدم التوكن المركزي). زرار ضريبة يضيف نسبة (افتراضي ١٤٪) فوق الصرف المعروض للعميل بس — الرقم الخام يفضل زي ما هو للإدارة والتقارير.
- **إيزي أوردرز**: معرّف المتجر (Store ID) — نفسه المستخدم في الويبهوك. حقل توكن API موجود لأي استخدام مستقبلي (النظام حاليًا بيشتغل بالويبهوك بس).
- **الإيميل**: بيانات IMAP لاستقبال إيميلات شركة الشحن (مُعدّة للتخزين بس حاليًا — لسه محتاجة worker منفصل يقرأها فعليًا لو عايز تشغيل تلقائي).
- **الواتساب**: العميل يطلب ربط جروب بالاسم، والإدارة تكمل الربط بالـ Group ID الحقيقي من تبويب **"الواتساب"**. بديل حي لملف `openclaw/wa-groups.json` الثابت — الأجنت يقدر يجيب الخريطة من `GET /api/wa-groups` بتوكن الـ Ingest بدل ما يقرا الملف.

**الأمان**: توكنز Meta/EasyOrders وكلمة سر الإيميل بتتشفّر بـ AES-GCM قبل التخزين (`TOKEN_ENC_KEY`)، وأي رد من السيرفر بيرجّع آخر ٤ حروف بس — القيمة الكاملة ما بترجعش تاني لأي متصفح حتى للإدارة.

---


- **كلمة المرور متخزّنة مشفّرة** بـ PBKDF2-SHA256، ١٠٠ ألف تكرار وملح عشوائي لكل حساب. ولا حد يقدر يقراها من قاعدة البيانات — ولا إنت
- **قفل مؤقت ١٥ دقيقة** بعد ٥ محاولات دخول فاشلة
- الرد على "إيميل مش موجود" بياخد نفس وقت "كلمة مرور غلط" — عشان ما يبانش مين مسجّل عندنا
- الجلسة موقّعة بـ HMAC-SHA256 وفي كوكي `HttpOnly` — ما ينفعش تتقرأ أو تتزوّر من المتصفح
- الجلسة مربوطة بمعرّف الحساب مش بالإيميل — فتغيير الإيميل ما بيكسرش الجلسة
- **الفلترة على السيرفر**: العميل بياخد بياناته هو بس من قاعدة البيانات، مش بيتبعتله كل حاجة ويتفلتر عنده
- كود دخول العميل ما بيرجعش في أي رد
- العميل ما ينفعش يعدّل إعدادات ولا حالة أوردر — تسجيل أوردر جديد بس
- مقارنة الأكواد بتاخد نفس الوقت دايماً عشان تمنع التخمين بقياس زمن الرد
- الويبهوك بيرفض أي طلب من غير الـ secret الصح

**ولسه ناقص:** استعادة كلمة المرور بالإيميل. حالياً الإدارة هي اللي بتصفّرها من تبويب الحسابات. ولو السيستم كبر، ضيف Cloudflare Rate Limiting على `/api/login` فوق القفل الموجود.

## حاجات تعرفها

- **آخر حفظ هو اللي بيتسجّل.** لو اتنين من فريقك بيعدّلوا نفس اللحظة، التاني بيمسح تعديل الأول. عندك دلوقتي مش مشكلة، ولو الفريق كبر نفصل الجداول.
- **التتبع مفيهوش إعادة محاولة.** لو تشغيلة فشلت، اللي بعدها هتلحق — بيشتغل كل ساعتين.
- **الكرون بتوقيت UTC** مش توقيت مصر.
- **لو فتحت `index.html` لوحده** من غير سيرفر، هيشتغل ببيانات تجريبية للعرض بس. ده مقصود.
