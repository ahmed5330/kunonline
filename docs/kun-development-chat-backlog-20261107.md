## تعريف حالة الإنجاز

1. **مطلوب / تحتاج مراجعة:** ذُكر في محادثة أو جرد لكن ليس لدينا إثبات نهاية-إلى-نهاية.
2. **كود في فرع / Draft PR:** لا يعني نشرًا أو بيانات حية.
3. **Merged:** دمج GitHub فقط، وقد يطلق نشرًا آليًا؛ يلزم إثبات إصدار Worker وAndroid وأجهزة حقيقية.
4. **CI ناجح:** لا يثبت نجاح Carrier/Firebase/Cloudflare أو صحة الطلبات.
5. **منشور ومثبت E2E:** يشمل نفس build والـSHA ونتيجة فعلية بإذن مناسب دون كتابة تجريبية على بيانات العملاء.

## ترتيب التنفيذ والبوابات الإلزامية

P0: تأمين عدم الكتابة على D1 العميل + إصلاح مصادقة الأدمن + مزامنة Easy Orders وفجوات الوفاق + فحص canonical D1 + backups/restore وrollback.  
P1: تدفق الطلبات والشحن والبحث مع تعديلات آمنة، إشعارات الموبايل، قياسات الأداء، صلاحيات Tester، تحصيل/محفظة.  
P2: الوظائف الأخرى: UX/UI، Clarity، مخزون، اشتراكات، POS، خدمات ومركز التكاملات.

**منع الضرر:** لا نشر Production/Preview، ولا migrations، ولا تغييرات على أوردرات/رصيد/شحنات/مخزون/اشتراكات حية إلا بعد نسخة قابلة للاسترجاع وSandbox مستقل وموافقة صريحة. Worker Production يوجه مسارات تشغيل إلى `PREVIEW_DB` رغم الاسم؛ لا تُستنتج canonical DB من اسمها فقط.

## فحوص قبول يجب إجراؤها قبل الإغلاق

- **الموبايل:** حالتا foreground/background، قفل الشاشة، 2 هواتف، صلاحيات 2+ متاجر، offline/resume، منع تسريب customer PII، قياسات p50/p95 بالزمن.
- **الطلبات:** حالات جديدة/مدفوع/تأكيد/إلغاء/تحضير/طباعة رسمية/شحن/تسليم/تحصيل/مرتجع مع Audit ودون double fees.
- **المزامنة:** إعادة تسليم webhook وout-of-order، تدوير الجلسة، إلغاء الصلاحيات، تنقل المتجر، حذف/نقل الأوردر، pagination، عدم فقدان cursor وتعارض concurrent updates.
- **التكاملات:** J&T official sandbox وEasy Orders مصدر القراءة؛ read-only schema/health والفرق بين Live وMock.
- **الأمان والمالية:** session logout 401/403، عدم فتح قسم بسبب نقص المحفظة دون مبرر، reconciliation ومراجعة الرسوم وCOD، منع وصول موظف لمتجر غير مسموح.
