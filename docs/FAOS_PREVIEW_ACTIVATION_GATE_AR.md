# FAOS — بوابة تفعيل المحاسبة واختبارات المطابقة على Preview
## الحالة المؤكدة: 18 أكتوبر 2026

العمل البرمجي في PR #185 معزول عن production. محرك FAOS يكتب فقط عندما تكون
`APP_ENV=preview` و`FAOS_WRITE_ENABLED=1` معًا، بعد نجاح صلاحيات المستخدم والمتجر.
قواعد FAOS القديمة لا تُستبدل، ولا يجري استيراد الطلبات الحقيقة تلقائيًا.

### اختبارات نجحت من خلال GitHub Actions
- قيد مزدوج مع إصدار حالة `draft -> posted` داخل معاملة SQLite/D1 واحدة؛ قاعدة البيانات تمنع نشر قيد غير متوازن.
- قيود مرحّلة غير قابلة للتعديل أو الحذف؛ قيد العكس مع سجل مصدر، ومنع تكرار المحاولة بمحتوى مختلف.
- فترة مالية مقفولة لا تسمح بقيد جديد حتى عند سباق الترحيل والإقفال.
- فصل متاجر العملاء، أدوار الاطلاع والكتابة، حماية من التلاعب بالـclientId.
- سيناريوهات طلبات وهمية: 4 طلبات و17 قيدًا وميزان مراجعة متوازن؛ COD وتحويل جزئي، مرتجع واسترجاع مخزون.
- SQLite تشغيل حقيقي للاستعلامات المحاسبية، وCloudflare Wrangler LOCAL D1 لترحيل SQL ومراجعة وجود مشغّلات الحماية.
- فحص القوائم للفترتين: قائمة الدخل للفترة، والميزانية تراكميًا حتى نهاية الفترة، مع التأكد من `assets = liabilities + equity`.
- مقارنة تقارير التشغيل مع الأستاذ الجديد لا تؤدي إلى اعتماد وهمي حتى لو تساوت الأرقام.

### فحص Preview البعيد — لم ينفذ
حدثت محاولة Read-Only عبر GitHub Actions من فرع PR باستخدام `environment: preview`.
تم رفض تشغيل المهمة قبل تخصيص runner، ولم يُنفذ SQL أو يُكتب أي شيء في Preview.
الإجراء الآمن: تمرير النسخة إلى مسار النشر Preview *المعتمد* بعد مراجعة PR؛
لا تُخفّف حماية البيئة أو تُنقل أسرار Cloudflare إلى فرع غير معتمد.

### البوابة اللازمة على Preview المعتمد
1. نسخ احتياطي/نقطة رجوع للـPreview D1 وتأكيد ملف الترحيل `0098_financial_ledger_v1.sql`.
2. من فرع Preview المصرح فقط، مراجعة قائمة الترحيلات المعلقة والتأكد أن الإضافات المطلوبة لا تمس جداول التشغيل القديمة.
3. تنفيذ الترحيل الإضافي للـPreview وحده؛ لا يطبق على production.
4. تشغيل endpoint `/api/accounting/faos/catalog` و`/api/accounting/faos/simulation` بحساب موظف مالي مختبري.
5. التأكد من ظهور مسار `الحسابات والحركات` بالقائمة الرئيسية، وفصل التحصيل المسجل والتقديري.
6. إنشاء متجر QA مستقل وتفعيل `FAOS_WRITE_ENABLED=1` للـPreview المراقب فقط ثم إضافة قيود QA؛ منع الإضافة على الإنتاج.
7. فحص طلب مكرر بزيادة قيمة وأرقام مستند مختلفة (409)، وثبات القيد الأصلي، وإقفال شهر QA وعكس القيد في شهر مفتوح.
8. إجراء اختبارات Browser فعلية مع أكثر من متجر وموظف محاسب/خدمة عملاء وصاحب متجر.
9. مقارنة كل طلب وAWB مع المستند المؤكد وتكاليف FIFO والباقات وتكاليف الشحن والاستقطاعات.
10. مطابقة كشف شركة الشحن وكشف البنك وتسويات بوابات الدفع وسجل المحفظة.
11. إعداد تقرير فرق مفتوح لكل متجر وشهر، يحدد مصدر الفرق ومسؤول المراجعة.
12. اعتماد السياسات الضريبية وبيع الأصل/الوكيل، وكذلك صلاحيات إقفال الشهر والأرصدة الافتتاحية.

### شروط عدم التفعيل
- لا تُدمج FAOS في تقارير المالية باعتبارها المصدر الرسمي حتى يصبح سجل الترحيل الآلي مرتبطًا بالأحداث الموثقة ومطابِقًا للصرف والدفاتر.
- لا تُدخل طلبات وهمية في المتاجر الحقيقية أو تمس رسوم المحفظة أو بوليصات J&T.
- لا يُوصف تقرير التحصيل المسجل بأنه رصيد بنك مؤكد بدون إثبات تسوية فعلية.
- لا يُسمح بكتابة FAOS في الإنتاج دون موافقة صريحة وخطة ترحيل منفصلة.
